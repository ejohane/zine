# End-to-end integration definition of done

The full agreed first release is the scope. Foundation and all four implementation
streams must operate together in this checkout; completed chats alone are not proof.
No deployment, merge, production test mutations or messages to people are authorized.

1. Shared migrations, schemas, exports, REST registration/OpenAPI, bindings, scheduler
   and account cleanup integrate without conflicting edits. Existing Foundation work
   is preserved. Wrapped migration is 0035; Delivery migration is 0036.
2. Native supports publication setup, draft composition from saved eligible content,
   cover/introduction/commentary/sections/order, explicit publication, both issue types,
   public reading, authenticated Save/Subscribe continuation, activity/mute, provenance,
   Wrapped selection and recovery/conflict/error states.
3. Public issue/publication pages work anonymously with server-rendered metadata,
   source links, safe previews, AASA and login action continuation. Existing private
   content remains private. Installed-app routes use the same stable URLs.
4. Private Sunday-to-Sunday Wrapped uses saved timezone and trustworthy save/open/finish
   evidence with historical coverage labels. Nothing is preselected or autopublished.
   Selected content becomes an ordinary weekly draft; post-publication additions lock.
5. Publication activity and optional push deliver new issues and daily additions,
   including mute/unsubscribe/recipient isolation/retry/digest/timezone guarantees.
   Bookmark saving preserves original source, reader notes and multiple discovery
   references, including when editor resources disappear.
6. All eleven product decisions and milestones A-D are reconciled in a final evidence
   matrix, with tested/observed/blocked status per requirement. Appropriate focused and
   repository gates pass on integrated code; meaningful failures are repaired.
7. Real authenticated local flows and direct native Simulator computer use establish
   actual behavior where capabilities permit. Checks/build/install/launch/auth/API
   target/UI interaction/visible result are reported separately. Real iMessage/APNs/
   universal-link/physical-device evidence is not inferred from fixtures or tests.
8. Hosted secrets/capabilities/provisioning or device prerequisites that cannot be
   provided locally are named precisely; remaining safe implementation is complete.
   A blocked required observation remains incomplete, never silently waived.
9. Dedicated local services are coordinated and stopped with their own orchestrator
   on session end, with ports released. No other task's services are stopped.
10. Final handoff lists changes, migrations, contracts, checks, integrated journeys,
    evidence limitations and release prerequisites. Work remains uncommitted unless
    separately authorized and all required pre-commit checks have passed.
